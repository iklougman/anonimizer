Privacy Pipeline Schema

The path a message takes from the chat API through detection, risk scoring, and pseudonymization, across the network boundary to the LLM, and back through leakage scanning and token restoration. Pseudonymized text is the only payload that crosses the boundary; every failure is fail-closed.

What the model sees

The provider only ever receives pseudonymized text — the system-preservation prompt plus token-substituted content. Raw patient data, the token vault, and the message store all stay inside the boundary. The completion it returns is also pseudonymized (it reproduces tokens verbatim); plaintext reappears only after resolve_tokens substitutes them back.

What the diagram does not yet show

Today the provider is called with a single message — no conversation history. The specced change sends full sanitized history as a message list and adds context-window trimming, per-conversation model selection, and an inline usage view. That history is the same pseudonymized sanitized_content shown here, so it crosses the boundary on the same teal arrow.
